# QQ 加载与拖动缓冲分析 · 2026-11-09

## 已确认的代码路径

用户反馈 QQ 的进度条缓冲比网易云明显，尤其快进到歌曲后段。尚未取得同一歌曲、同一音质、同一网络下的计时样本，因此不能断言某一项就是此次现象的唯一根因。

已按本机安装的 MyGo Music 0.1.22 对应源码确认：

- 音乐源公开接口只返回 URL、类型、音质、文件大小和请求头。实际下载、缓存、解码和 seek 由宿主负责，插件不能通过该接口提供自定义 Range reader。
- `download.run` 使用单个顺序 GET，只接受 HTTP 200，没有 Range 请求。下载器从头持续写入缓存文件。
- `downloadReader.Read` 在目标偏移尚未下载时等待；超过 250ms 的读取/seek 饥饿会显示缓冲。
- 完整歌曲可以缓存复用；宿主会预取下一首，但不会预取当前歌曲任意后续偏移。
- FLAC seek 会用二分/割线式位置猜测寻找帧，最多多轮读取远处偏移。顺序下载尚未到目标时，每个位置仍须等待。QQ 无损选为 FLAC，文件通常大于 128/320kbps MP3，但本反馈的具体歌曲和音质尚未测量。

因此，点到尚未下载的后段，所需时间至少受“当前已下载位置 → 目标偏移”的数据量和 CDN 吞吐影响。这不是单纯增加插件超时或延迟可以修复的。两个平台共用同一宿主下载器，差异可能来自地址解析、CDN 或实际文件大小；需要同曲同音质实测才能进一步定量。

## 插件侧优化

QQ 每次未缓存地址解析先请求歌曲详情，再请求 vkey；网易云已有并发地址请求合并。0.1.4 为 QQ 增加：

- 相同会话代际、歌曲 ID、音质的并发请求合并。
- 成功结果 30 秒内存复用，最多保留 64 项；对象按浅拷贝返回。
- 失败不保存为成功，过期后重新获取；退出或登录主动清空，代际变化不复用旧项，也不把旧代际晚完成的结果存入当前代际。
- 不把签名 URL 写入磁盘、日志或错误，不改变音质回退和服务端授权判断。

它只减少播放地址获取延迟，尤其是相同解析并发或短时间重复解析。它**不能**让宿主在尚未下载到目标偏移时立即播放，也不能据此声称真实 CDN 缓冲已提速。

## 真正的后续优化位置

若实测瓶颈是 seek 等待，应在上游宿主实现支持 HTTP Range 的按需范围读取、范围缓存与相应的取消/回退策略，同时处理 CDN 不支持 Range、URL 续期和文件校验。该改动需要播放器侧验证，不在本插件 ZIP 中。不能用降低无损到 MP3、扩大人为等待或绕过账号授权来隐藏问题。
