# 组合音乐源的边界

本插件通过 MyGo Music 的公开 JavaScript 音乐源接口工作，不修改播放器。目标版本是 MyGo Music 0.1.20 及兼容后续版本。

- 单一音乐源 ID：`music-fusion`。内部 ID 分为 `netease:<原始 ID>`、`qqmusic:<原始 ID>`。歌手、专辑、歌单、播客和页面都遵循同样的命名空间。
- 两个 provider 使用独立的存储前缀、会话和登录流程。默认 Sign In 依次登录网易云、QQ；插件设置可单独选择登录目标及 QQ/微信方式。设置改变后上游会重读账号，可显示目标账号的登录按钮。
- 搜索分别维护两个服务的游标，合并返回页，按标准化标题完全相等、前缀、包含、歌手、其他排序。同一首歌的两种版权版本保留，显示平台标签。某服务失败时保留另一服务的结果，并在主页提供状态。
- 新建歌单是插件本地歌单，持久化完整歌曲元数据和来源。服务端歌单作为只读入口展示，避免把混合来源歌曲错误写入某一平台。
- 插件数据通过 `host.storage` 原子写入上游私有数据目录。会话没有使用旧应用钥匙串；需要重新扫码。上游插件存储是权限受限的本地 JSON，不提供钥匙串加密。
- 旧版 `playlists.json` 通过离线命令转换为导入 JSON，再粘贴到插件设置；不会自动读取旧应用目录。QQ 缺少歌曲 MID 时在访问时按数字 ID查询详情；MediaMID 由播放前详情请求恢复。
- 对网络请求设定超时，QQ 续期合并并保护登录/退出竞态。播放权限以服务端完整播放链接为准，不以 VIP 标签决定。原版播放器的暂停、缓冲、解码和失败后的队列跳转不受音乐源插件控制。
- 无第三方 API 服务器、无子进程权限。安装包内包含构建产物、完整源码和第三方许可；开发依赖仅用于本地构建和测试。

## 兼容性验证方式

Node 测试覆盖组合层、会话状态机与 provider 请求。Go 集成脚本通过 overlay 让未修改的上游 `internal/plugin` 加载最终 JS，使用合成 HTTP 响应检查 moejs 兼容性。已执行与未执行的项目见 [validation.md](validation.md)，其中单独记录实际登录反馈；不会将测试脚本的存在视为已经验证通过。
