# 组合音乐源的边界

本插件通过 MyGo Music 的公开 JavaScript 音乐源接口工作，不修改播放器。目标版本是 MyGo Music 0.1.20 及兼容后续版本。

- 单一音乐源 ID：`music-fusion`。内部 ID 分为 `netease:<原始 ID>`、`qqmusic:<原始 ID>`。歌手、专辑、歌单、播客和页面都遵循同样的命名空间。
- 两个 provider 使用独立的存储前缀、会话和登录流程。默认 Sign In 依次登录网易云、QQ；插件设置可单独选择登录目标及 QQ / QQ 音乐 App / 微信方式。设置改变后上游会重读账号，可显示目标账号的登录按钮。
- 搜索分别维护两个服务的游标，合并返回页，按标准化标题完全相等、前缀、包含、歌手、其他排序。同一首歌的两种版权版本保留。默认返回原始歌名，防止平台后缀污染系统媒体信息；可通过 `showSourceInTitle=true` 开启平台标签。平台身份始终由 ID 决定。某服务失败时保留另一服务的结果，并在主页提供状态。
- 新建歌单是插件本地歌单，持久化完整歌曲元数据和来源。内部记录保留 `fusionOriginalName` 以支持平台标签开关；返回给宿主前移除此内部字段。读取 0.1.1 的缓存、歌单和最近播放时恢复原始标题，导入去重指纹仍按旧规则计算。服务端歌单作为只读入口展示，避免把混合来源歌曲错误写入某一平台。
- 插件数据通过 `host.storage` 原子写入上游私有数据目录。会话没有使用旧应用钥匙串；需要重新扫码。上游插件存储是权限受限的本地 JSON，不提供钥匙串加密。
- 旧版 `playlists.json` 通过离线命令转换为导入 JSON，再粘贴到插件设置；不会自动读取旧应用目录。QQ 缺少歌曲 MID 时在访问时按数字 ID查询详情；MediaMID 由播放前详情请求恢复。
- 对网络请求设定超时，QQ 续期合并并保护登录/退出竞态。QQ 相同歌曲/音质的播放地址解析合并，成功结果按会话代际在内存复用 30 秒，不写磁盘；失败不缓存，登录、退出及代际变化不复用旧地址。播放权限以服务端完整播放链接为准，不以 VIP 标签决定。原版播放器的暂停、缓冲、解码和失败后的队列跳转不受音乐源插件控制。0.1.22 的下载路径是单个顺序 GET 且仅接受 200，无 Range 请求；插件 URL 接口不能替代宿主的范围下载/拖动策略。详见 [缓冲分析](playback-buffering.md)。
- 无第三方 API 服务器。QQ 音乐 App 扫码是可选子进程功能：仅允许启动包内六个明确命名的辅助程序路径，需用户在 MyGo 中授权。原 QQ / 微信登录和普通搜索播放不启动程序，不依赖此授权。辅助程序只提供 crypto/rand 随机数据及直连腾讯的 MQTT 5 / WSS 传输；JS 负责匿名设备、CreateQRCode、最终 Login 交换及账号验证。取消、超时、完成和 VM 关闭会结束子进程；中间授权不写入存储，错误不输出令牌。辅助程序和 Go 依赖的完整源码与许可随 ZIP 提供。
- “搜索音源”及 `qq:` / `netease:` 前缀仅限制该次搜索和建议，不切换登录账号，不更改已有歌单及播放来源。缓存包含音源范围；每个平台保持独立游标。侧栏按音源查看使用 Browse.Sections 分组展示最近搜索的已加载页、最近播放和混合歌单。Track.Source 由宿主改写为插件 ID，公开 Track API 无徽标字段，因此全局混合搜索、队列无法单独显示插件自定义逐曲徽标。

## 兼容性验证方式

Node 测试覆盖组合层、会话状态机与 provider 请求。Go 集成脚本通过 overlay 让未修改的上游 `internal/plugin` 加载最终 JS，使用合成 HTTP 响应检查 moejs 兼容性。已执行与未执行的项目见 [validation.md](validation.md)，其中单独记录实际登录反馈；不会将测试脚本的存在视为已经验证通过。
